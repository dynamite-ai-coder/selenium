# AI Browser Agent

A production-ready web application that lets you drive a **real, visible Chromium
browser** with an AI agent powered by **DeepSeek**, from a ChatGPT-style chat UI,
while watching the browser live through an embedded **noVNC** preview.

The whole stack (virtual display, desktop, browser, VNC and web app) runs from a
single Docker container and is ready to deploy on **Render**.

---

## 1. What it does

- Password-protected web interface (session cookie, HTTP-only).
- Chat panel where you type browser tasks, e.g. *"Open Google and search for OpenAI"*.
- DeepSeek LLM drives a [Browser Use](https://github.com/browser-use/browser-use) agent.
- Chromium runs **headed** inside Xvfb + XFCE, never headless.
- Live browser view is embedded with noVNC in the right-hand panel.
- Real-time WebSocket status: `task_started`, `agent_action`, `task_completed`,
  `task_failed`, `browser_connected`, `browser_disconnected`, `error`, ...
- Upload files to the agent and download files generated by the browser.
- Stop a running task cleanly.

Only safe, concise progress information is shown - never hidden chain-of-thought.

## 2. Architecture

```
Browser (user)
  │  HTTPS  + session cookie
  ▼
FastAPI (app/main.py)                     ┌──────────────────────────────┐
  ├── /            chat UI (static/)      │ Chromium (headed)            │
  ├── /ws          WebSocket event bus    │   ▲ CDP :9222                │
  ├── /api/task    starts AgentRunner     │   │                          │
  ├── /api/upload  file uploads           │ XFCE on Xvfb :99             │
  ├── /api/download/{name} downloads      │   ▲                          │
  └── /websockify  authenticated proxy ───┼─► x11vnc :5900               │
                                          │   ▲                          │
                                          │ websockify :6080 (noVNC)     │
                                          └──────────────────────────────┘
```

- `app/main.py` - FastAPI routes, auth middleware, WebSocket endpoints, noVNC proxy.
- `app/auth.py` - password check, signed session cookies, login rate limiting.
- `app/config.py` - all settings from environment variables.
- `app/llm.py` - LLM provider abstraction (DeepSeek by default).
- `app/agent.py` - async Browser Use runner with safe status events + cancellation.
- `app/browser.py` - connects Browser Use to the visible Chromium over CDP.
- `app/websocket.py` - connection manager / event bus.
- `static/` - dark chat UI + login page.
- `scripts/` - startup order: Xvfb -> XFCE -> x11vnc/noVNC -> Chromium -> uvicorn.
- `Dockerfile`, `render.yaml` - container and Render blueprint.

## 3. Environment variables

| Variable | Default | Description |
| --- | --- | --- |
| `APP_PASSWORD` | *(empty)* | Password for the web UI. **Required.** |
| `DEEPSEEK_API_KEY` | *(empty)* | DeepSeek API key. **Required for tasks.** |
| `DEEPSEEK_MODEL` | `deepseek-v4-flash` | Model id (`deepseek-chat`, `deepseek-reasoner`, ...). |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI-compatible endpoint. |
| `SESSION_SECRET` | auto-generated | Stable random value so sessions survive restarts. |
| `COOKIE_SECURE` | auto-detect | Force the `Secure` cookie flag. |
| `PORT` | `10000` | HTTP port (Render sets this automatically). |
| `HOST` | `0.0.0.0` | Bind address. |
| `DISPLAY` | `:99` | X display used by Xvfb/XFCE/Chromium. |
| `SCREEN_WIDTH` / `SCREEN_HEIGHT` | `1920` / `1080` | Virtual desktop size. |
| `BROWSER_HEADLESS` | `false` | Keep `false` for the live preview. |
| `CDP_URL` | `http://127.0.0.1:9222` | Chromium DevTools endpoint. |
| `BROWSER_PROFILE_DIR` | `browser_profile` | Persistent browser profile. |
| `UPLOADS_DIR` / `DOWNLOADS_DIR` | `uploads` / `downloads` | File directories. |
| `MAX_UPLOAD_MB` | `10` | Upload size limit. |
| `AGENT_MAX_STEPS` | `100` | Browser Use step limit. |
| `AGENT_TASK_TIMEOUT` | `900` | Task timeout in seconds. |

**Never commit `.env`.** Use `.env.example` as a template.

## 4. Local installation (without Docker)

```bash
cp .env.example .env          # edit APP_PASSWORD and DEEPSEEK_API_KEY
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# optional: start the graphical stack locally (Linux desktops only)
bash scripts/start_desktop.sh
bash scripts/start_novnc.sh
bash scripts/start_browser.sh

uvicorn app.main:app --host 0.0.0.0 --port 10000
```

Without a local display, the agent falls back to launching a headed browser via
Browser Use, and the live preview will be unavailable.

## 5. Docker usage

Build and run:

```bash
docker build -t ai-browser-agent .
docker run --rm -p 10000:10000 \
  --env-file .env \
  --shm-size=1g \
  ai-browser-agent
```

Then open <http://localhost:10000> and log in with `APP_PASSWORD`.

Useful overrides:

```bash
docker run --rm -p 10000:10000 \
  -e APP_PASSWORD='change-me' \
  -e DEEPSEEK_API_KEY='sk-...' \
  -e DEEPSEEK_MODEL='deepseek-v4-flash' \
  -e SCREEN_WIDTH=1600 -e SCREEN_HEIGHT=900 \
  --shm-size=1g \
  ai-browser-agent
```

The container starts, in order: Xvfb, XFCE, x11vnc, websockify/noVNC, Chromium
(headed, CDP on 9222), then uvicorn on `$PORT`. Only port `10000` needs to be
published - VNC (5900) and websockify (6080) are bound to localhost, and the
noVNC WebSocket is proxied through FastAPI after authentication.

## 6. Configuring DeepSeek

1. Create an API key at <https://platform.deepseek.com>.
2. Set `DEEPSEEK_API_KEY` in `.env` (local) or Render Environment Variables.
3. Optionally set `DEEPSEEK_MODEL` (default `deepseek-v4-flash`).
4. Use a different OpenAI-compatible provider by changing
   `DEEPSEEK_BASE_URL`; the browser agent is provider-agnostic through
   `app/llm.py`.

The UI shows friendly errors for missing keys, rate limits, timeouts and
connection failures. Secrets are never sent to the frontend or written to logs
(log output is filtered by `app/utils.py:RedactingFilter`).

## 7. Deploying to Render

1. Push this repository to GitHub.
2. In Render choose **New > Blueprint** and select the repository.
   Render reads `render.yaml` and creates one Docker web service.
3. When prompted, set:
   - `APP_PASSWORD` - your login password
   - `DEEPSEEK_API_KEY` - your DeepSeek API key
   - `DEEPSEEK_MODEL` - optionally override the default
   `SESSION_SECRET` is generated automatically; `COOKIE_SECURE=true` is preset.
4. Wait for the health check on `/health` to pass, then open the service URL.

Render sets `$PORT`; the app listens on `0.0.0.0:$PORT`. Internal VNC ports are
never exposed publicly.

## 8. Authentication

- Every page, API route, WebSocket and the noVNC proxy require a valid session.
- `APP_PASSWORD` is only used server-side; it is never embedded in JavaScript.
- Sessions are HMAC-signed HTTP-only cookies backed by an in-memory server-side
  store; logout revokes them immediately.
- Failed logins are rate-limited per client IP (`LOGIN_MAX_ATTEMPTS`,
  `LOGIN_LOCKOUT_SECONDS`).

## 9. How the live browser preview works

Chromium renders to the virtual X display `:99` (Xvfb). XFCE provides the
desktop, `x11vnc` exports the display on `127.0.0.1:5900`, and `websockify`
serves noVNC on `127.0.0.1:6080`. The frontend embeds
`/novnc/vnc_lite.html?path=websockify`, and FastAPI proxies the WebSocket at
`/websockify` - only authenticated sessions get through, so no public VNC port
or password is needed.

## 10. Uploading and downloading files

- Use the **+** button in the composer to upload files (default limit 10 MB).
- Filenames are sanitized; uploads are stored in `uploads/` with a unique prefix.
- Attached files are passed to the agent as `available_file_paths`.
- Files generated by the browser land in `downloads/` and appear in the **Files**
  list with download links (`/api/download/...`), protected by the same session.
- Path traversal is prevented by `app/utils.py:safe_join`.

## 11. Stopping a task

Click **Stop** (or the server timeout expires). The runner calls the agent's
stop hook, waits briefly, then cancels the asyncio task, closes the agent and
reports `task_stopped`. Only one task can run at a time; a second request gets
`409 Agent is currently busy.`

## 12. Troubleshooting Chrome / Xvfb / noVNC

| Symptom | Fix |
| --- | --- |
| Browser badge stays red | `curl 127.0.0.1:9222/json/version` inside the container; check `/tmp/chromium.log`. |
| noVNC panel empty | Check `/tmp/x11vnc.log` and `/tmp/websockify.log`; ensure port 6080 is up. |
| Browser crashes / OOM | Increase the Render plan (2 GB+ recommended) or lower `SCREEN_WIDTH`/`SCREEN_HEIGHT`. |
| XFCE does not start | Ensure `dbus-x11` is installed and `HOME` is writable by the runtime user. |
| `Target closed` errors | Restart the task or use **Reconnect browser**; the monitor reconnects automatically. |
| Slow first task | Chromium cold start + model latency; the first action can take a few seconds. |

## 13. Render memory considerations

Chromium + XFCE + Xvfb + Python typically need **1-2 GB RAM**. The blueprint
uses the `standard` plan. If you use a smaller plan, reduce
`SCREEN_WIDTH`/`SCREEN_HEIGHT`, disable browser extensions, and expect OOM
restarts. `--shm-size` does not apply on Render; the image passes
`--disable-dev-shm-usage` instead.

## 14. Security considerations and limitations

- Do not expose the service without `APP_PASSWORD`; all routes fail closed when
  it is unset.
- The agent can do anything a normal user with that browser can do. Only run
  tasks you are authorized to perform.
- Abusive requests (credential stuffing, CAPTCHA bypass, brute forcing, ...) are
  rejected by a server-side filter, but this is a safeguard, not a sandbox.
- Secrets are redacted from logs; never put secrets into task text.
- This is a general-purpose browser automation tool, not an anonymity tool:
  websites can see the Render datacenter IP.
